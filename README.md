# موسوعة الفتاوى — مكتبة رقمية لمجموعة فتاوى ابن تيمية

منصة قراءة وبحث مبنية حول **مجموعة فتاوى شيخ الإسلام ابن تيمية** (٣٧ مجلداً، ١١٬٣١٤ صفحة). الهدف: جعل موسوعة ضخمة كان يصعب البحث فيها متاحةً للباحثين بثوانٍ، مع الحفاظ على الصورة الأصلية كمرجع معتمد وإتاحة تحميل الملف الأصلي لمن يريد القراءة خارج الواجهة.

**النسخة الحية:** https://book-of-fatwa-collection.safealigoog.workers.dev

## لماذا هذا المشروع؟

معظم النسخ المتاحة على الويب هي ملفات PDF ضخمة بلا طبقة نصّ، ما يجهد الباحث الذي يريد الوصول إلى فتوى أو مسألة بعينها. الموسوعة نفسها تحتوي على فهارس مطبوعة ممتازة (خاصة المجلدين ٣٦ و٣٧ «الفهارس العامة»)، لكنها صور غير قابلة للبحث.

هذه المنصة تبني **فهرساً رقمياً موثوقاً** أعلى هذه الصور، ثم تسمح بفتح الصفحة الأصلية مباشرة.

## المنهجية

1. **الصورة هي الأصل**: صفحات PDF مصوّرة بدقة ≈٣٠٠ dpi وجودة JBIG2، تُحوَّل إلى WebP بنسختين (مصغّرة للعرض، كاملة للتكبير). لا يُعدَّل المتن إطلاقاً.
2. **الفهارس أولاً**: تُستخرج عناوين الأبواب من الإشارات المرجعية المدمجة في PDF، وهي نظيفة وموثوقة.
3. **OCR موجّه لا شامل**: يُشغَّل التعرف الضوئي **على صفحات الفهرس المطبوع فقط**، لا على المتن كاملاً؛ لأن OCR العربي غير دقيق بما يكفي لاعتماده نصّاً شرعياً. نتائجه تُستخدم للإرشاد وتُوسم بذلك في الواجهة.
4. **التوحيد للبحث**: إزالة التشكيل، توحيد الهمزات و«ة/ه» والأرقام، حتى يستطيع الباحث العثور على المادة بكتابته المعتادة.
5. **الشفافية**: كل نتيجة بحث تفتح الصفحة الأصلية؛ تنبيه دائم بأن الصورة هي المرجع.

## الواجهة

القارئ RTL بالكامل، مع ثلاثة أوضاع عرض محفوظة في المتصفح: **ليلي**، **بيج** مريح للعين، و**نهاري** بخلفية رمادية-بيضاء. الوضع الأول يتبع إعداد النظام، وتتغيّر ألوان الواجهة και صورة الصفحة نفسها مع الوضع (تعتمة وتقليل تباين في الليلي، تدفئة خفيفة في البيج). مكوّنات الحركة مأخوذة من [Magic UI](https://github.com/magicuidesign/magicui) ومكيّفة مع ألوان المشروع (`Animated Theme Toggler`، `Shimmer Button`، `Blur Fade`، `Aurora Text`)؛ تعمل الحركة عبر `motion/react` وتُوقَّف تلقائياً مع `prefers-reduced-motion`. إطار الصفحة يحيط به قوس ذهبي ثابت بدل الشريط المتحرك.

للتنقل بين الصفحات ثلاث طرق واضحة: زرا **السابق/التالي** الكبيران في شريط القراءة، شريط تنقل عائم أسفل الصورة يعرض رقم الصفحة الحالية والمجاورة، أو مفتاحا `←` (التالي) و`→` (السابق). يمكن أيضاً كتابة رقم الصفحة مباشرة.

أدوات القراءة تشمل شريط **شدة الإضاءة** (٦٠–١٤٠٪) لتخفيف السطوع أو زيادته دون تغيير الوضع، و**المراجعي** لحفظ الصفحات والعودة إليها محلياً في المتصفح، و**التظليل** لتحديد موضع على الصورة بالسحب والعودة إليه لاحقاً (تُحفظ العلامات محلياً أيضاً، والصورة الأصلية تبقى كما هي). زر **مشاركة** يوفّر نسخ رابط الصفحة، ومشاركة الجهاز، والإيميل، وواتساب، وإكس، وفيسبوك؛ الرابط يحمل رقم المجلد والصفحة `?v=vNN&p=N`.

## الحقوق

المتن تراث إسلامي عام، والنسخة متاحة مجاناً على [Internet Archive](https://archive.org/details/mft37). رابط «تحميل الأصل» في القارئ يفتح ملف PDF المطابق للمجلد مباشرة: `https://archive.org/download/mft37/mftNN.pdf` (حيث NN رقم المجلد). الكود تحت ترخيص MIT. لا تدّعي المنصة ملكية النص أو الصور، وتحتفظ بمصدرها الأصلي.

## التشغيل محلياً

```bash
npm install
python -m venv .venv
.venv\Scripts\pip install -r scripts/requirements.txt

.venv\Scripts\python scripts/build_manifest.py     # استخراج بيانات كل المجلدات
.venv\Scripts\python scripts/prepare_volume.py v01 # تجهيز مجلد
npm run ocr:index -- v01                            # OCR لصفحات الفهرس فقط
npm run dev
```

## النشر على Cloudflare

الواجهة تُبنى كأصول ثابتة (`npm run build`) وتُنشر عبر Wrangler:

```bash
npm run build
npx wrangler deploy
```

الصور الكاملة والملفات الأصلية تُرفع إلى R2، ويُضبط عند البناء:

```
VITE_FILES_BASE=https://<r2-public-domain>
VITE_ORIGINAL_BASE=https://<r2-public-domain>
```

### بدائل تخزين مجانية (بدون بطاقة دفع)

| الحل | مجاني؟ | مناسب هنا؟ | ملاحظات |
|---|---|---|---|
| **Internet Archive** | نعم، بلا بطاقة | **الأفضل للمدى الطويل** | نُشئ عنصراً جديداً ونرفع صور `vNN/full/`؛ ثم `VITE_FILES_BASE=https://archive.org/download/<ITEM-ID>`. الجهة نفسها التي تستضيف ملفات PDF الأصلية. |
| **مستودع GitHub / Git LFS** | نعم | ممكن لكن ثقيل | LFS يمنح ~10 GB تخزين و~10 GB نقل شهرياً؛ raw github لا يدعم LFS دائماً، وحجم المستودع يكبر كثيراً. |
| **Blogger / Google** | نعم | ممكن لكن فوضوي | يحتاج إعادة صياغة الروابط، وضغطاً من Google للصور، واعتماداً على روابط غير مضمونة للربط المباشر. |
| **Firebase / Supabase / Cloudflare D1** | نعم بحدود | لا للصور | قواعد بيانات وخوادم خلفية ممتازة للبيانات المنظّمة، لكنها ليست مخزناً للصور؛ D1 تحديداً غير مصمم لتخزين blobs بحجم ٢ GB. |

لتحضير رفع الأرشيف:

```bash
.venv\Scripts\python scripts/make_archive_bundle.py
```

ينتج `build/archive/fatwa-full-images.zip` داخله `vNN/full/pNNNN.webp` ونسخة من الواجهة في `site/`. خطوات الربط:

1. أنشئ حساباً مجانياً على archive.org (لا بطاقة مطلوبة) وتأكد من بريدك.
2. اختر **Upload files** وارفع الملف `fatwa-full-images.zip`؛ انتظر حتى ينتهي فك الضغط والمعالجة.
3. دوّن **Item Identifier** الذي يظهر في الرابط، وجرّب متصفحياً:
   `https://archive.org/download/<ITEM-ID>/v37/full/p0001.webp`
4. أعطني هذا الرابط لأضبط `VITE_FILES_BASE` وأعيد البناء والنشر.

لا يحتاج ذلك أي تغيير في الواجهة؛ القارئ يقرأ الصورة الكاملة عند أي تكبير بمجرد ضبط العنوان، ويعود للمصغّرة إذا لم يُضبط.

### التخزين المؤقت والهاتف

- `public/_headers` يضبط الكاش سنة كاملة لملفات `files/` و`data/` و`assets/`، مع إبقاء `index.html` قابلاً للتحديث فوراً. الصفحات ثابتة لذلك لا توجد مشكلة في الكاش الطويل.
- في الهاتف يبدأ الفهرس **مغلقاً** ويفتح كدرج فوق الصفحة مع خلفية معتمة وزر إغلاق؛ ويبدأ التكبير ٢٠٠٪ مع تمرير أفقي حتى تبقى القراءة مريحة.

## البنية

| المسار | المحتوى |
|---|---|
| `public/data/manifest.json` | أسماء المجلدات وعدد الصفحات وفهارس الأبواب لكل ملف |
| `public/data/prepared.json` | المجلدات المجهّزة للقراءة فعلياً |
| `public/data/volumes/vXX.json` | تفاصيل مجلد واحد وخريطة الصفحات |
| `public/data/ocr/vXX-index.json` | نصوص صفحات الفهرس المطبوع بعد الـ OCR |
| `public/files/vXX/thumbs/` | صور مصغّرة مدمجة في المستودع |
| `build/images/vXX/full/` | صور كاملة للرفع إلى R2 (غير مضمّنة في Git) |
| `public/robots.txt`, `public/sitemap.xml`, `public/manifest.webmanifest`, `public/_headers` | بيانات SEO وملفات الوصول والتهيئة للنشر |
| `scripts/` | خط أنابيب الاستخراج والتحويل والفهرسة |
